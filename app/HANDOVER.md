# Передача проекта напарнику

Для разработчика, который подключается к работе над AllSeattle (allseattle.org). Здесь — что
где лежит, как запустить, как выкладывать и на чём уже обжигались. Ключей в этом файле нет:
они передаются отдельно (см. «Ключи»).

## Что это за проект

- **`app/`** — сам портал: Next.js 16 + Payload CMS 3 + PostgreSQL. Живой сайт —
  https://allseattle.org, админка — https://allseattle.org/admin.
- **Корень репозитория** — первый этап, статичный демо-прототип на GitHub Pages
  (casaantipo-a11y.github.io/allseattle). Его не трогаем: из него `pnpm seed` берёт демо-новости
  и картинки, а CSS прототипа перенесён в портал.
- Сайт на английском (аудитория — США). Заказчик и переписка — на русском.

Документация, которую стоит прочитать до первой правки:

| Файл | Что в нём |

## Ключи

Пять файлов в `app/` (в git не попадают, `.gitignore`):

| Файл | Что внутри |
|---|---|
| `.env` | всё для локальной разработки: локальная база, `PAYLOAD_SECRET`, ключи R2, Resend, Turnstile, Telegram, логин первого админа для `pnpm seed` |
| `.env.local` | тестовый ключ Stripe (sandbox) и его webhook-секрет, ключ Resend, **живой ключ Stripe заказчика** (`STRIPE_LIVE_SECRET_KEY`, ограниченный `rk_live_…`) |
| `.env.neon.local` | `DATABASE_URL` **продакшен-базы** Neon |
| `.env.r2.local` | ключи **продакшен-хранилища** R2 |
| `.env.vercel.local` | `PAYLOAD_SECRET` продакшена и адрес сайта |

Переданы архивом `allseattle-keys-*.7z` (AES-256, пароль — отдельным сообщением). Распакуй в
`app/`. Никогда не коммить, не вставляй в чаты и документы. **Не меняй `PAYLOAD_SECRET`
продакшена** — все пользователи сайта и админки выйдут из аккаунтов.

`.env.neon.local` и `.env.r2.local` — это живые данные. Скрипты, которые их используют
(`pnpm seed:prod` и т. п.), пишут в настоящую базу.

## Запуск локально

Нужны Node.js 20.9+ и pnpm. Postgres ставить не нужно — `pnpm db` поднимает встроенный.

```bash
cd app
pnpm install
pnpm db        # терминал 1: локальная база на 127.0.0.1:5433 (данные в ./.pgdata)
pnpm seed      # терминал 2, один раз: админ + демо-контент (новости, компании, машины, вакансии…)
pnpm dev       # http://localhost:3000, админка /admin
```

Логин локального админа — `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` из `.env`. Локально
письма лучше не слать: запускай `RESEND_API_KEY= pnpm dev`. Для форм с капчей — тестовые ключи
Turnstile: `TURNSTILE_SITE_KEY=1x00000000000000000000AA TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA`.

Оплата локально идёт через тестовый Stripe (`sk_test_…` в `.env.local`), карта `4242 4242 4242 4242`.
Stripe не может прислать вебхук на localhost — пакет после оплаты локально сам не включится
(на живом сайте включается).

Проверок перед коммитом три: `pnpm typecheck`, `pnpm lint`, а для вёрстки — замер по ширинам
(скилл `measure`, см. `.claude/rules/layout-check.md`). Тестов в проекте нет.

## Как выкладывать

Работаем в ветке `stage3`. Выкладка:

```bash
git fetch origin
git merge-base --is-ancestor origin/main stage3   # main должен быть предком stage3
git branch -f main stage3 && git push origin main && git push origin stage3
cd app && npx vercel deploy --prod --yes          # нужен вход в Vercel-аккаунт проекта
```

Сборка на Vercel сама применяет миграции (`pnpm migrate && pnpm build`). Сообщение
`Error: spawn EPERM` в конце вывода CLI — это телеметрия Vercel, не ошибка деплоя: смотри строку
`readyState: READY`. Пока проект на Hobby, второго человека в Vercel не добавить — выкладывает
владелец аккаунта (или переходим на Pro, $20/мес за участника).

Договорённость с заказчиком: на прод — только после его (или Александра) «да».

## Миграции базы

- Любое изменение полей коллекции или глобала = миграция: `pnpm migrate:create имя`.
- **Генератор каждый раз пытается удалить столбцы хранилища R2** (`media._objectkey`,
  `documents._objectkey`, `documents.prefix`): локально плагин R2 выключен, и он их не видит.
  Эти строки из сгенерированной миграции **удаляй руками**, а в снимок схемы (`.json` миграции)
  возвращай эти столбцы — см. `20261019_152002_site_socials_x` и `20261020_162638_seo_texts`.
- Локальная база в dev-режиме обновляет схему сама (push), миграции на неё не применяются.

## Правки данных на продакшене

Меню, настройки сайта, страницы About/Contact/Terms/Privacy, SEO-тексты разделов
(Settings → SEO texts), категории — это данные в базе, не код. Их меняют в админке.

Если в админку зайти нельзя, можно разовым скриптом через Payload Local API с ключами
продакшена — так устроен `scripts/prod.mjs` (берёт `.env.neon.local`, `.env.r2.local`,
`.env.vercel.local` и отказывается работать не с Neon). После изменения — сбросить кэш сайта
(`revalidateSite` из `src/scripts/revalidate-site.ts`), иначе прод до часа показывает старое.

## Ловушки, на которые уже наступали

- **CSS страницы перебивает `components.css`** — страничные файлы обёрнуты в `[data-page="…"]`
  и грузятся позже. Подробно — `app/CLAUDE.md` → «Traps met in practice».
- **Никакой анимации, только `min-width` медиа-запросы, все отступы из токенов** — правила
  заказчика, см. `CLAUDE.md` и `design.md`.
- **Рекламные места — это проданный товар.** Не добавлять и не убирать без запроса.
- **Страницы с `generateStaticParams`, которые читают `searchParams`, падали 500** на всех
  непредсобранных путях (рубрики Shopping/Leisure, 21.10.2026). Такие страницы — динамические,
  без `generateStaticParams`.
- **Возврат из Stripe «выкидывал» из аккаунта**: Payload отбрасывает cookie входа при переходе
  с другого сайта (защита CSRF). Исправлено в `src/lib/account.ts` — для открытия страницы
  cookie принимается. Отдельно: админка и кабинет посетителя используют один cookie
  (`payload-token`), поэтому в одном браузере открытая админка выбивает вход в кабинет —
  тестируй кабинет в окне инкогнито.
- **Список аккаунтов посетителей (`customers`) закрыт даже для админа через REST**, создать
  посетителя через REST нельзя (403) — только регистрацией на сайте.
- **`pnpm dev` иногда не подхватывает правку константы** — перезапусти dev-сервер.
- **Логи Vercel на Hobby хранятся около часа** — разбирать ошибку прода нужно сразу.
