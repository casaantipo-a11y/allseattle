AllSeattle — доступ к Vercel для второй машины + включение поддоменов
24.10.2026

Зачем: сейчас выкладывать сайт и менять настройки Vercel может только владелец аккаунта
(mijckela-4959). На второй машине (где работает Claude Code) входа в Vercel нет, поэтому там
нельзя ни проверить настройки, ни задеплоить. Добавить второго человека в проект на тарифе
Hobby нельзя, поэтому доступ даём токеном.


ЧАСТЬ 1. ТОКЕН ДЛЯ ВТОРОЙ МАШИНЫ (5 минут)

1. Открой https://vercel.com/account/settings/tokens
   (аватар справа вверху → Account Settings → Tokens).
2. Нажми Create Token.
   - Name: allseattle-second-machine
   - Scope: свой аккаунт (mijckela-4959)
   - Expiration: 90 days (не «No expiration»: если токен утечёт, он сам перестанет работать)
3. Нажми Create и скопируй токен. Vercel покажет его один раз.
4. Передай токен напарнику НЕ в общий чат и не в группу: только в личное сообщение,
   лучше одноразовой ссылкой (например, https://onetimesecret.com). После передачи удали
   сообщение у себя.

Важно знать: на Hobby токен даёт доступ ко всему твоему аккаунту Vercel, не только к этому
проекту. Отозвать его можно в любой момент там же: Tokens → токен → Delete.

Что делает напарник на своей машине (для справки):
   - в PowerShell: setx VERCEL_TOKEN "<токен>"
   - перезапускает VS Code
   - из папки app: npx.cmd vercel link --yes --project allseattle
   Дальше Claude Code сможет смотреть настройки и деплоить — деплой только по явному «да».


ЧАСТЬ 2. ВКЛЮЧИТЬ ПОДДОМЕНЫ (10 минут, можно сделать сразу, не дожидаясь части 1)

Зачем: у компаний с пакетами Luxury и Premium должен открываться свой адрес вида
starbucks.allseattle.org. DNS домена уже на Vercel (Андрей переключил 23.10), код готов.
Сейчас starbucks.allseattle.org резолвится, но по HTTPS не отвечает: в проекте нет
такого домена и выключена функция.

1. Vercel → проект allseattle → Settings → Domains → Add.
   Впиши: *.allseattle.org → Add.
   Если Vercel спросит про редирект — без редиректа. Сертификат выпустится сам
   (обычно за пару минут, статус станет Valid Configuration).

2. Settings → Environment Variables → Add New. Две переменные, окружение только Production:
   ENABLE_SUBDOMAINS = true
   ROOT_DOMAIN       = allseattle.org
   (без кавычек, без пробелов, без https://)

3. Deployments → у последнего деплоя с меткой Production → ⋯ → Redeploy → Redeploy.
   Это пересоберёт тот же код, что сейчас на сайте, но уже с новыми переменными.
   Новый код из репозитория при этом не уезжает.

4. Проверка: открой https://starbucks.allseattle.org
   - если открылась страница сайта (или «страница не найдена» на дизайне сайта) — работает;
   - если ошибка сертификата или «сайт недоступен» — подожди 10 минут и проверь,
     что у *.allseattle.org в Domains статус Valid Configuration.

5. Напиши в чат «поддомены включены». Дальше Андрей в админке у компании с пакетом
   Luxury или Premium вписывает в поле Subdomain короткое имя (например, starbucks).


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

- Сайт allseattle.org перестал открываться после Redeploy: Deployments → предыдущий
  Production-деплой → ⋯ → Promote to Production. Это откат за минуту.
- Не трогай в Settings → Domains записи allseattle.org и www.allseattle.org и DNS-записи
  send, resend._domainkey, _dmarc — на них работает сайт и отправка писем.
